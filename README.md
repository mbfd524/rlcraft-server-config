# RLCraft服务器：4核8G起步够几个人？配置、开服方式与套餐价格对照

搜「RLCraft服务器」的人，问的其实不是同一个问题。有人手里已经有一台 8 核 16G 的机器，只想确认够不够；有人连 Linux 都没碰过，关心的是能不能不敲命令就把朋友拉进来。

RLCraft 官方整合包的版本停在 Minecraft 1.12.2，作者最后一次发版是 2023 年 6 月，之后没有新版本。这意味着版本这件事没什么可纠结的，真正需要花时间的是另外三件事：需要多少内存和 CPU、用什么方式开服、国内买哪一种机器。

下面按实际决策顺序来。

## 先钉死版本，否则后面全是白折腾

RLCraft 的服务端固定在 `1.12.2 + Forge`，所以它需要 **Java 8**。这一点每年都会绊住一批人：服务器上装了 Java 17 或 21，Forge 直接起不来，报错还很难看出原因。托管平台一般会自动选运行环境，自己装的话记得手动指定 Java 8。

另外，CurseForge 上还有一些跑在 1.16 或 1.20 上的「RLCraft」，那些是其他人重制的整合包，和官方 2.9.3 不是同一个东西，两边的玩家互相进不了对方的服务器。你和朋友必须用同一个官方版。

服务端压缩包里有个细节值得提前知道：官方的 server 包**不含 Forge 安装器和启动脚本**，需要自己装 Forge（1.12.2-14.23.5.2864 这一支或更高）再写启动命令。

还有四个 `server.properties` 的开关，整合包作者明确要求改：`allow-flight=true`、`difficulty=3`、`max-tick-time=-1`、`enable-command-block=true`。最后一条尤其别关——关掉之后部分建筑会生成不完整，村民也可能不刷出来。

> 客户端和服务端的整合包版本一定要完全一致，`2.9.3` 对 `2.9.3`。有玩家自己加了 VanillaFix、BetterFPS 这类优化模组的话，先让他删掉；OptiFine 只能用 1.12.2 HD U G5。

## 内存到底给多少：4GB 能开，6–8GB 才是舒服的起点

各家的建议区间并不一致，原因主要是统计口径不同——有人只算服务端本身，有人把预生成地图和视距一起算进去了。把公开资料里的数字摊开看：

| 同时在线人数 | 常见「最低」建议 | 常见「推荐」建议 |
| --- | --- | --- |
| 1–5 人 | 4GB | 5–6GB |
| 5–10 人 | 5–6GB | 8GB |
| 10–20 人 | 6–8GB | 10–12GB |
| 20 人以上 | 8–10GB | 12GB 以上 |

整合包作者自己在说明里写的是「建议分配 4GB 或以上」，有托管商直接写「至少 8GB」。差异这么大，是因为 RLCraft 虽然模组很多（不同统计口径在 120 到 170 之间），但它跑在 1.12.2 上，每个区块和实体的内存占用比 1.20+ 的包小一圈。所以 4GB 确实能启动，也能玩，只是人一多、一跑图就顶不住。

倒过来也有坑：**别把机器内存全分给服务端**。Java 的垃圾回收在堆很大的时候反而会产生更长的停顿，老版本的 1.12.2 服务端尤其明显。常见做法是留出系统本身要用的部分，分配给服务端的最多占机器总内存的 70%–80%。启动参数上，`-Xms` 设成 `-Xmx` 的一半左右，让 JVM 按需增长。

## 真正卡你的往往是 CPU 单核，不是内存

如果内存给够了还是卡，问题基本不在内存。RLCraft 里制造压力最大的模组是 Lycanites Mobs：它刷怪比原版激进得多，还会随地形动态生成地牢结构，这些逻辑都压在服务器的单线程主循环上。Minecraft 的主循环本来就吃单核，模组把它进一步放大。

表现出来就是 TPS 掉、方块点了半天没反应，但内存还有大把空闲。

对应的处理手段有几条，都能在配置文件里改：

- 降低 `config/lycanitesmobs/general.cfg` 里的 `mobSpawnChance`
- 服务端视距压到 8 或更低，模拟距离 4 左右
- 提前预生成地图，别让区块生成和玩家游玩同时进行——这是最容易见效的一条
- 限制每个区块的实体堆积上限，`max-entity-cramming` 调到 8 左右

所以选机器的时候，一个单核主频高的 4 核，通常比单核弱一些的 8 核更适合开 RLCraft。雨云这边把「CPZU 单核跑分」直接印在了游戏云的产品页上，就是让你按这个维度挑，而不是只看核心数。

## 三种开服路线，按你的动手能力选

**路线一：云应用一键部署，适合完全不想碰系统的人。**

雨云有一套基于 Kubernetes 的容器应用平台（云应用 RCA），应用商店里有现成的 RLCraft 应用，点安装、选配置、等日志跑完就能进服。它按小时计费，关机不持续扣费，配置可以随时升降。官方教程里给的配置建议是 2 核 4G 以上，10 人以上建议 4 核 8G。

一个必须提醒的坑：选共享 IP 时，默认端口 25565 大概率已经被别人占了，得换一个随机端口，然后让朋友用 `IP:端口` 的格式进服。想用标准端口就得买独立 IP。

另外，官方教程提到云应用对新用户有 15 天免费试用（总资源上限 8 核 8G）——这类活动的具体条款会调整，以你注册后控制台里显示为准。

**路线二：游戏云 VPS + 面板，适合想省事但要长期开服的人。**

买一台游戏云，装 MCSM 面板或雨云自研的游戏面板，剩下一键开服、备份、CPU 升降级、MySQL 都在网页上点。这条路线的成本比云应用可控，因为计费方式能锁死，不用担心挂着不管的费用。

**路线三：自己装，适合打算长期折腾、或者手上已有闲置机器的人。**

Windows 上用远程桌面拉服务端上去，双击启动脚本就行，整合包服务端里一般自带 Windows 版 JDK8；Linux 上就是 Java 8 + 上传服务端 + 启动脚本的常规流程。自由度最高，出问题也得自己查。

## 优惠怎么用才不浪费

**新用户首月 5 折。** 通过推广链接注册、绑定微信之后，系统会发一张首月 5 折券。这是雨云给新用户的固定力度，适合拿来先买一个月试稳定性——RLCraft 的配置需求估计得再准，也不如自己跑一晚上看看 TPS 实在。

**年付 7 折。** 长期付费有折扣，年付是 7 折，这一点多个渠道一致。至于季付和半年付的折扣档位，只在一份第三方整理里看到（9 折 / 8 折），下单前在支付页自己确认一下更稳。

**券和年付能叠。** 折扣券用在新购上、年付折扣用在周期上，两者不冲突，这也是上面那张机型表里「年付折合」数字的算法来源。

## 开起来之后，还有几件小事值得做

**提前预生成世界。** RLCraft 的地形里有火龙巢穴、战斗塔、Lycanites 地牢，第一次生成非常费时。至少预生成 3000 格半径，之后玩家跑图就不会一边玩一边卡。

**硬盘要留余量。** 服务端文件本身 5–10GB，世界文件还会随着探索持续变大。雨云游戏云默认给 30G 系统盘 + 20G 数据盘，预生成加上几个人开荒，用掉大半不奇怪，硬盘可以随时扩容。

**备份靠下载，别指望运气。** 云应用的备份方式是把 `world` 文件夹打包下下来；面板开服的话一般有现成的一键备份。RLCraft 玩崩一次世界，重开的代价是几十小时。

**卡顿先看 TPS 再看 CPU。** 如果服务器卡但内存空闲，先降视距和刷怪率，再考虑升配置。反过来，内存长期贴着上限、频繁 GC，那就是该加内存了。

## 几个常被问到的问题

**2 核 4G 能开 RLCraft 吗？**
能启动，也能玩，但基本限定在一个人或者两三个人小范围活动。官网对 200+ mod 整合包给出的承载就是 1 人，这不是保守说法。

**20 个人要什么配置？**
按公开建议，内存要往 10–12GB 以上走，雨云的 6 核 12G 超高端档对 200+ mod 整合包标注的是 8 人。人数真到 20 人这个量级，建议直接上独立公网 IP 和更高档配置，共享 IP 的端口映射会成为限制。

**RLCraft 会更新到新版本吗？**
按目前情况，官方包自 2023 年 6 月起没有新版本，也不会迁到新版本 MC。对开服的人是好事——配置一次，长期不用跟着升级折腾。
